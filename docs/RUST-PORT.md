# Rust port (experimental)

Branch: `experimental/rust-port`

The desktop shell is being ported from Electron/Node to **Tauri 2 + Rust**.
The renderer (`ui/`) is intentionally shared: it talks to the local HTTP bridge
on `127.0.0.1:7100` for everything except six window-level calls, and the Rust
build exposes those through Tauri commands via `ui/tauri.js`.

The Electron build remains the shipping product until the Rust port reaches
parity; nothing in `src/`, `tests/e2e.js`, or `electron-builder.yml` changed.

## Layout

```
src-tauri/
  Cargo.toml            crate `poly-vault` (bin + lib)
  tauri.conf.json       product metadata, frontendDist ../ui, global Tauri API
  capabilities/         core window permissions
  icons/                copied from build/ (regenerated by npm run icons)
  src/
    main.rs             thin binary entry
    lib.rs              Tauri builder, window, single instance, bridge spawn
    commands.rs         Tauri commands backing window.assetVault
    state.rs            app state, JSON stores, enrichment lanes, job pruning
    store.rs            JsonStore (atomic write, corrupt-file backup)
    library.rs          scanner: tree, assets, kinds, previews, timestamps
    autotags.rs         store-text -> tag rules (port of autoTags.js)
    enrichment.rs       meta merge semantics + queue state
    unity_store.rs      Unity Asset Store lookup + HTML extraction (reqwest)
    bridge.rs           axum server implementing the HTTP bridge contract
    mcp.rs              MCP JSON-RPC tools, guarded exports, agent sessions
    paths.rs            path.resolve equivalent, containment guard, helpers
    time.rs             ISO-8601 / epoch helpers
```

## Run

```powershell
# one-time: rustup + VS Build Tools (C++ workload) are required
cargo run --manifest-path src-tauri/Cargo.toml
```

The window loads `ui/index.html`; the bridge starts first, so the renderer's
`/api/status` poll succeeds immediately.

Useful environment variables kept from the Electron build:

| Variable | Effect |
| --- | --- |
| `ASSETVAULT_USER_DATA` | Override the `Poly Vault` data folder (isolated runs) |
| `ASSETVAULT_BOOT_LIBRARY` | Register a library before the window opens |
| `ASSETVAULT_NO_ENRICH=1` | Disable Unity Asset Store lookups (tests/offline) |

`ASSETVAULT_DEBUG` (renderer console relay) is Electron-only for now.

## HTTP bridge parity

Implemented with axum, same routes, payloads, guards, and status codes:

| Route | Behaviour |
| --- | --- |
| `GET /api/status` | name/version/time/libraryCount/libraries/unitySeenAt |
| `GET /api/library` | full scan + auto-enqueue enrichment |
| `GET /api/enrichment` | `{state, pending, active, done, message}` |
| `POST /api/update` | scoped rescan, returns `{libraries, targets, status}` |
| `GET/PUT /api/meta` | per-folder descriptions, library containment enforced |
| `GET/PUT /api/tags` | normalized lowercase tags, 64 cap |
| `POST /api/tags/apply` | bulk add/remove across paths, containment enforced |
| `GET /api/preview` | allowlisted extensions, ETag/304, Last-Modified, streamed file |
| `POST /api/import-job` | creates pending job, prunes to 200 terminal jobs |
| `GET /api/import-jobs` | full queue for the UI |
| `GET /api/unity/import-jobs` | active queue for the Unity plugin + `unitySeenAt` |
| `POST /api/unity/import-jobs/:id/:action` | complete/failed/processing + note |
| `GET /api/agents` | connected agent sessions, recent exports, MCP URL |
| `POST/DELETE /mcp` | MCP Streamable HTTP (`2025-06-18`), five tools, session header |

`GET /__diag` is a stub: it drove DOM clicks through Electron's
`executeJavaScript`, which has no Tauri equivalent in the current design.

## Window API shim

`ui/tauri.js` maps the preload surface onto commands only when
`window.__TAURI__` exists, so the Electron build still uses `src/preload.js`:

```js
assetVault.addLibrary()             -> invoke('add_library')
assetVault.removeLibrary(id)        -> invoke('remove_library', { id })
assetVault.getState()               -> invoke('get_state')
assetVault.getServerInfo()          -> invoke('get_server_info')
assetVault.openInExplorer(path)     -> invoke('open_path', { targetPath })
assetVault.fetchUnityDescription(n) -> invoke('fetch_unity_description', { name })
```

## Storage

Same files under `%APPDATA%\Poly Vault` (or `ASSETVAULT_USER_DATA`), same JSON
shape and keys, so the two builds can be pointed at one data folder for
comparison:

`asset-vault-settings.json`, `asset-vault-jobs.json`,
`asset-vault-tags.json`, `asset-vault-meta.json`, `asset-vault-exports.json`.

## Tests

Rust unit tests mirror the Node smoke fixtures:

```powershell
cargo test --manifest-path src-tauri/Cargo.toml
```

They cover the nested-library scan (asset count, container aggregation, kinds,
previews), tag derivation (`["furniture","low-poly"]`), meta merge protection
for hand-written descriptions, job pruning, path containment, JSON store
corruption recovery, the bridge's tag normalization/scope sanitising, and the
MCP hub (destination/subfolder guards, export layout, session snapshot).

The bridge also has integration tests that bind an ephemeral port and walk the
real contract: status, `/api/library` scan, tag containing guard (403),
tag round-trip, preview `200` + `If-None-Match` `304`, import job creation,
`unitySeenAt` advancing on a Unity poll, and `initialize` → `tools/list` →
`poly_vault_export_asset` → `GET /api/agents` over `/mcp` (including a refused
export into a library).

The Electron smoke/e2e suites still run against `src/` and are unchanged.

### Verification on this branch

```
cargo test           22 passed, 0 failed
node tests/smoke.js  SMOKE PASS
node tests/e2e.js    E2E PASS
```

Manual runs of `src-tauri\target\debug\poly-vault.exe` and the release build
(`cargo build --release`) with `ASSETVAULT_USER_DATA`,
`ASSETVAULT_BOOT_LIBRARY` and `ASSETVAULT_NO_ENRICH=1`: both bound
`127.0.0.1:7100`, `/api/status` reported the registered library, and
`/api/library` returned the fixture scan with preview, kinds and timestamps.
The release run also spawned its WebView2 processes, so `ui/index.html` loaded
inside the Rust shell. A release run was also driven over `/mcp`: initialize
returned `poly-vault`, an export copied the fixture mesh into a project folder,
and `/api/agents` listed the session and export. `unitySeenAt` stays `0`
without the Unity plugin: only the C# plugin polls `/api/unity/import-jobs`,
the renderer polls `/api/status`.

`tests/e2e.js` also carried a pre-existing race: it asserted the
"Re-import to Unity" label immediately after selecting the card, while the
renderer only refreshes job state on a 5 s poll, so the suite failed on `main`
(`d3b4f84`) too. The wait now includes the completed-job button state.

### Build output (Windows x64)

```powershell
cargo build --release                        # src-tauri\target\release\poly-vault.exe            (~16 MB)
npx @tauri-apps/cli@2 build --bundles nsis   # src-tauri\target\release\bundle\nsis\
                                             #   Poly Vault_0.4.2_x64-setup.exe                  (~4.5 MB)
```

Both are unsigned, and the Tauri build is not wired into CI yet. The CLI warns
that the identifier `com.polyvault.app` ends in `.app`, which conflicts with the
macOS bundle extension — change it before producing macOS bundles.
